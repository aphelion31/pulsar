# 01. Overview

## What Pulsar replaces

| Chatwoot                              | Pulsar                                               |
| ------------------------------------- | ---------------------------------------------------- |
| Ruby on Rails API                     | Rust, axum (`src/`)                                  |
| ActiveRecord                          | sqlx with hand-written SQL, same tables              |
| Sidekiq + Redis background jobs       | Work done inline in the request (see limits below)   |
| ActionCable + Redis pub/sub           | `src/cable.rs`: same wire protocol, in-memory streams |
| devise_token_auth                     | `src/auth.rs`: same headers, same bcrypt token hashes |
| ActiveStorage (disk)                  | `src/storage.rs`: same tables and on-disk key layout  |
| Vue 3 dashboard, Vue widget           | React Router v8 SPA (`web/`), React widget route      |

One process serves the API, the websocket, uploaded files and the built frontend. Resident memory is about
7 MB at idle and about 20 MB under load (see the README benchmark).

## Request paths

**Dashboard API.** The React app stores the `access-token`, `client` and `uid` headers returned by
`POST /auth/sign_in` and sends them on every request. `CurrentUser` (in `src/common.rs`) checks them against
the bcrypt hashes in `users.tokens`, or accepts an `api_access_token` header from `access_tokens`.
Account-scoped handlers then call `require_account`, which returns the user's role in that account or 401.

**Realtime.** The browser opens `/cable` and subscribes to `RoomChannel` with its `pubsub_token`. Agents also
join the `account_<id>` stream. Handlers broadcast `{event, data}` through `st.hub`: `to_inbox` reaches inbox
members, account admins and the contact's widget session; `to_account` reaches every agent in the account.
Presence is a heartbeat map with a 20 second TTL.

**Files.** Uploads go to `STORAGE_DIR` under `ab/cd/<key>`, the Rails disk-service layout, with a row in
`active_storage_blobs`. URLs are `/rails/active_storage/blobs/redirect/<id>--<hmac>/<filename>`; the HMAC is
keyed by `SECRET_KEY_BASE`, so a URL cannot be guessed from a blob id.

**Website widget.** A customer site loads `/sdk.js`, which adds a launcher and an iframe pointing at
`/widget?website_token=...`. `POST /api/v1/widget/config` creates or resumes the visitor and returns an HS256
token; every later widget call sends it as `X-Auth-Token`. A forged or missing token is 401.

## Limits

- **Single instance.** Pub/sub and presence are in memory. Running two instances needs Postgres
  LISTEN/NOTIFY or Redis fan-out in `src/cable.rs`.
- **No background job runner.** Work Chatwoot does in Sidekiq (email delivery, automation execution,
  campaign sending, channel webhooks) is not ported yet. Automation rules and campaigns are stored but not run.
