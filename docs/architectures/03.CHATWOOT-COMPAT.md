# 03. Chatwoot compatibility

## Schema

`migrations/0001_schema.sql` is generated from Chatwoot's `db/schema.rb` by `tools/schema2sql.rb`, a small
stub of the ActiveRecord schema DSL that prints SQL. It needs no Rails install:

```bash
ruby tools/schema2sql.rb ../chatwoot/db/schema.rb > migrations/0001_schema.sql
```

Regenerate it when Chatwoot's schema changes, then check the handlers that read changed tables. The schema
needs the `vector`, `pg_trgm` and `pgcrypto` extensions.

## Auth

`users.tokens` holds devise_token_auth entries `{client_id: {token: bcrypt, expiry}}`; Pulsar reads and
writes the same format, so sessions and passwords move between Chatwoot and Pulsar. `access_tokens` rows work
as `api_access_token` headers for API clients and agent bots.

## API shapes

Handlers return the JSON the Chatwoot jbuilder views produce, including enum names (`"open"`, `"resolved"`),
unix-second timestamps and `display_id` as the public conversation id. Realtime events use the names and
payloads of Chatwoot's `ActionCableListener`.

## Ported

Auth, profile, accounts, realtime websocket, conversations, messages, attachments and avatars, contacts,
inboxes (API and web widget), agents, teams, labels, canned responses, custom attributes, custom filters,
notifications, search, macros (with execution), automation rules (stored), webhooks (stored), campaigns
(stored), agent bots, dashboard apps, companies, audit logs, custom roles, v2 reports, the public website widget.

## Not ported

Channel integrations (WhatsApp, Facebook, Instagram, email IMAP/SMTP, SMS, Telegram, Line), outgoing webhook
delivery, automation execution, campaign sending, mailers, help center, Captain AI, SLA, MFA and SSO.
Unported `/api` routes answer `501` so gaps are visible rather than silent.
