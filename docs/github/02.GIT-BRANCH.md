# 02. Branch

Pulsar follows Chatwoot's branch model (`develop` for integration, `master` for releases), with one addition:
every work branch carries a `PLR-<number>` ticket prefix.

| Branch                          | Purpose                                                                     |
| ------------------------------- | --------------------------------------------------------------------------- |
| `master`                        | Released code only. Moves when a release or hotfix is merged. Tagged `vX.Y.Z` |
| `develop`                       | Default and integration branch. All work branches start here and merge back |
| `PLR-NNN/<type>-<description>`  | Feature, fix, refactor, docs or chore work, cut from `develop`              |
| `release/<version>`             | Release preparation, cut from `develop`, merged into `master` and `develop` |
| `hotfix/<version>`              | Urgent production fix, cut from `master`, merged into `master` and `develop` |

Direct pushes to `develop` and `master` are blocked by the `pre-push` hook; work arrives by pull request.

## Work branch name

```text
PLR-<number>/<type>-<description>
```

- **`PLR-<number>`**: three or more digits, zero-padded: `PLR-001`, `PLR-042`, `PLR-1205`. Use the ticket
  number if there is one, otherwise the next number after the highest `PLR-*` branch on origin.
- **`<type>`**: one of `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `build`, `ci`, `chore`, `core`,
  `style`, `revert`. `core` is for changes to the foundation the rest builds on (router, auth, cable, schema).
- **`<description>`**: free text in lowercase kebab-case.

Examples:

```text
PLR-001/feat-boilerplate
PLR-014/fix-widget-forged-token
PLR-015/refactor-conversation-serializer
PLR-016/core-cable-postgres-fanout
PLR-017/docs-deploy-guide
```

Not allowed: `feature/reports`, `PLR-1/feat-x` (number too short), `PLR-015/Feat_Reports` (not kebab-case),
`PLR-015/reports` (no type).

## Rule: pull before you work

Every time you switch to `develop`, pull before doing anything else:

```bash
git switch develop
git pull origin develop
```

A stale `develop` produces branches based on old code and conflicts in the PR.

## Create a work branch

```bash
scripts/new-branch.sh feat-reports-v2          # picks the next PLR number, cuts from origin/develop
scripts/new-branch.sh PLR-020/fix-login-loop   # or give the full name
```

By hand:

```bash
git fetch --prune
git branch -r | grep -oE 'PLR-[0-9]+' | sort -t- -k2 -n | tail -1   # highest number on origin
git switch -c PLR-021/feat-short-description origin/develop
```

## Release and hotfix branches

These keep Chatwoot's names and are the only branches without a `PLR` prefix.

```bash
git switch -c release/0.2.0 origin/develop     # bump version, final fixes, then PR into master
git switch -c hotfix/0.2.1 origin/master       # urgent fix, PR into master, then into develop
```

After a release or hotfix merges into `master`, merge `master` back into `develop` through a PR so the two
do not drift. See [03.GIT-PR-FLOW.md](03.GIT-PR-FLOW.md).

## Enforcement

`pre-commit` and `pre-push` (`scripts/check-branch.sh`) reject any other branch name. `pre-push` also blocks
direct pushes to `develop` and `master`. Install with `git config core.hooksPath .githooks`.
